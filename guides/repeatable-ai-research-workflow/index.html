Build a Repeatable AI Research Workflow: From Source Collection to Evidence-Based Reporting

A six-step method for using a model as a research assistant while keeping sources, claims and verification under your control.

By Leila Haddad, Guides Editor

Using a model for research goes wrong when the model becomes the source. It works when the model assists a process in which you choose the sources, check the claims and own the conclusion. This six-step workflow is designed to be repeated, so each project benefits from the last.

1. Define the question

Write one sentence stating what you need to know and who it is for. Add what would count as an answer, and what is out of scope. A model given a vague question returns a vague overview. A model given a precise question can help you search precisely.

2. Collect sources yourself

Gather the documents you will rely on: primary sources first, such as papers, filings, official data and original statements. Save each with its title, publisher, date and link. Retrieval-augmented generation research showed that answers improve when a model works from supplied text, which is why the quality of this collection matters more than any prompt.

3. Ask the model to work from your sources

Give the model the documents and tell it to answer only from them. Ask it to quote or point to the passage supporting every claim, and to say plainly when the sources do not contain the answer. Use the model for the jobs it handles well:

  • Extracting key points from long documents
  • Comparing what two sources say about the same topic
  • Listing open questions and conflicts between sources

Anthropic’s guidance on building with models recommends starting with simple steps, and a prompt chain fits here: extract, then compare, then draft, with a check between each stage.

4. Verify every claim you will publish

This is the step that cannot be delegated. The SIFT method offers a compact checklist for evaluating information: stop, investigate the source, find better coverage, and trace claims to their origin. Apply it to anything the model reported.

For each claim, record:

  • The sentence as you intend to state it
  • The source passage that supports it, with a link
  • Whether you read that passage yourself
  • A status: confirmed, partly supported, or unverified

Remove or soften anything unverified. Be especially strict with numbers, quotations, dates and names.

5. Draft from the verified list

Write the piece from your verified claims. A model can help with structure and clarity at this stage, but give it only the verified material. Review the draft for any statement that does not appear in your list.

6. Keep a research log

Record the question, sources, prompts that worked, errors you caught and the final claim list. This log lets someone else reproduce your work and lets you improve the process. After a few projects, patterns in the errors you caught show where to add checks.

A short template

FieldEntry
QuestionOne sentence
SourcesTitle, publisher, date, link
ClaimsStatement, source passage, status
Open questionsWhat the sources could not answer
ReviewerName and date

Following the same steps each time makes the results consistent and the mistakes easier to find.
