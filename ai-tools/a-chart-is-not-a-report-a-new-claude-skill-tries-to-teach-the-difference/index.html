A Chart Is Not a Report. A New Claude Skill Tries to Teach the Difference

A Claude Skill that transforms raw data into accurate, interactive reports with clear narratives and purposeful visuals.

By Amara Ellison, Senior Editor, Models and Industry

Published Oct 21, 2026

6 min read

Ask an AI model to "turn this spreadsheet into a dashboard," and most people expect the obvious: it reads the columns, picks a few charts and draws them. The expectation is reasonable, and the output usually looks fine. What it skips is the work that makes a dashboard useful. Nobody has decided what the viewer should conclude, whether the underlying numbers can be trusted, or where the eye should go first. The result is a chart, and a chart is not a report. Animated Data Reports, a skill built by the creator who publishes as prompt2me, is an attempt to close that gap. It does not give Claude new abilities. It changes the order in which Claude does things, and that change explains most of what the skill produces.

From five prompts to one workflow

The skill began as five prompts written for Claude Design, each describing one kind of animated report: a dashboard, an executive slide deck, a timeline that plays through time-series data, a performance scorecard and a narrated data story. Each prompt named the layout, the animation and the interaction. A prompt is a single instruction, though, and a single instruction can't anticipate the file it will meet. It doesn't say what to do when a spreadsheet has a "Total" row at the bottom, when there is no date column, or when the data contains no targets to compare against. Those are the moments when generated reports go wrong, so the skill wraps the five prompts in a procedure that handles them.

What a skill is

A skill is a folder of instructions that Claude reads when a request matches its description. Only a short description is always visible. The main instructions load when the skill is triggered, and the longer reference files load only if they are needed. Animated Data Reports uses that arrangement. It has one core file, a separate reference for each of the five formats, a design guide covering motion and accessibility, and a data-profiling script. If you ask for a scorecard, Claude reads the scorecard reference and leaves the other four alone.

Profiling before drawing

The first step is unglamorous. A bundled Python script opens the file, which can be CSV, TSV, Excel, JSON or Word, and classifies every column as a date, a measure, a category or an identifier. It reports ranges and missing values and flags rows that look like totals. The total-row check shows why this step matters. A chart that sums a column including its own grand total reports a figure roughly twice the true one, and nothing about the finished graphic reveals the error. The script catches it before anything is drawn. In the one sample run the creator has done, a small sales file with a deliberately planted total row, the script identified the date, measure and category columns and flagged the planted row. The skill also tells Claude to compute every figure in code and embed the results in the page, rather than estimating from a glance at the data. The numbers on screen then come from arithmetic rather than from a model's impression of the table.

The story comes before the pixels

Once the data is understood, the skill asks Claude to settle three things privately: who the audience is, what single sentence they should leave with, and which three to five findings support it. Chart and slide titles then state those findings. "West drove most of the growth" tells a busy reader something, while "Revenue by region" only labels what they are looking at. This is the part that separates a report designer from a chart generator. A chart that doesn't support a finding is decoration, and the skill's instruction is to cut it.

Motion with a job to do

The animation rules follow from the same logic. In a dashboard, each chart builds in a fixed order: axes first, so the viewer knows the frame, then the bars or lines, then the labels. In an executive deck, a headline number counts up from zero and then locks to its exact value, so the final figure on screen is the true one rather than wherever the animation happened to stop. In the time-series format, the playback pauses at the largest spikes and drops and explains each one. The reasoning is about attention, not decoration: sequence directs where people look. That is a design argument, not a measured result, and it has limits. A count-up cannot rescue a wrong number, and too much motion becomes noise. The skill therefore caps entrance animations at under a second, forbids endlessly looping effects, and shows the final state immediately for viewers who have asked their devices to reduce motion.

Guardrails against misleading charts

Several rules address honesty rather than appearance. The skill tells Claude to use only figures present in the file, to start bar charts at zero and to label units and periods. For a scorecard, if the file contains no targets, Claude is told not to invent any. It compares each metric with the prior period or a trailing average, labels the benchmark plainly and offers to add real targets. If a Word document holds prose but no numeric tables, the skill says to report that fact and offer a qualitative summary, not to fabricate charts. The default output is a single HTML page with no build step, built to work on a phone screen and in light or dark themes.

What is not yet known

The skill's maker has been candid about its status. The packaging passed the structural validator in Anthropic's skill-creator tooling, and the profiling script worked on the one sample file. But the skill has not been tested against a baseline of Claude without it, and three test prompts, covering a dashboard, an executive deck and a timeline, have been written but not run. Whether reports built with the skill are better than reports built without it is, for now, an open question. There is also a structural limit. The skill's final step has Claude re-check its numbers against the source. That is a useful habit, but it is the same system checking its own work, and it does not replace a person reading the result.

Back to the dashboard

The opening assumption, that asking for a dashboard gets you a dashboard, turns out to be half right. You get something that resembles one. What this skill adds is everything that happens before and after the drawing: understanding the file, deciding the story, computing the numbers and checking them. Whether that extra procedure produces measurably better reports is something the next round of testing will show. The design idea behind it, that a report should be planned around what the viewer needs to understand before anything animates, is sound regardless.
